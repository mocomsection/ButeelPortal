Improve and modernize the visual design of the EXISTING prototype without redesigning the product structure.

IMPORTANT:
The current product structure, page hierarchy, workflows, forms, fields, features, information architecture, navigation logic, and business logic have already been intentionally designed.

DO NOT:

* rebuild the product
* restructure pages
* change workflows
* remove features
* remove fields
* add unnecessary new features
* rename business concepts
* reorganize modules
* significantly change the current layout logic
* replace the existing visual identity
* change the overall brand color direction
* turn the product into a generic dashboard template

Preserve the existing product and improve the DESIGN QUALITY only.

# PRIMARY GOAL

Make the existing prototype feel:

* more modern
* cleaner
* more polished
* more professional
* more premium
* easier to understand
* visually consistent
* less cluttered
* more intentional
* production-ready

Keep the current general color palette and visual identity.

Refine it rather than replacing it.

The result should feel like a professionally designed modern SaaS product, while still clearly being the same product.

# DESIGN SYSTEM DIRECTION

Use modern SaaS design-system principles inspired by:

* shadcn/ui
* Radix UI
* Linear
* Stripe
* Vercel

Use these only as design-quality references.

DO NOT copy their branding or make the interface look exactly like those products.

The existing brand identity must remain recognizable.

# 1. PRESERVE CURRENT COLORS

Keep the current primary colors and overall color direction.

Improve only:

* contrast
* semantic usage
* neutral colors
* background hierarchy
* borders
* hover states
* selected states
* disabled states
* success / warning / error / information states

Do not introduce many new colors.

Reduce unnecessary color variation.

Use the existing brand color primarily for:

* primary actions
* selected navigation
* important interactive states
* links
* focus states

Avoid using the primary brand color decoratively everywhere.

# 2. IMPROVE TYPOGRAPHY

Create a clearer typography hierarchy across the existing interface.

Standardize:

* page titles
* section titles
* card titles
* body text
* labels
* helper text
* table text
* captions
* status text

Improve font size, weight, line-height, and spacing.

Avoid excessive bold text.

Important information should be easy to scan.

Secondary information should feel visually quieter.

Do not change the content or terminology.

Keep the existing components and functionality, but visually standardize repeated UI patterns.

Make sure the following look consistent everywhere:

* buttons
* inputs

* radio buttons
* switches
* tabs
* tables
* badges

Standardize the existing buttons.

40px

Avoid:

* overly rounded buttons
* excessive shadows
* unnecessary gradients
* oversized buttons

Primary actions should be visually obvious.

Secondary actions should not compete with primary actions.

# 6. INPUTS AND FORMS

Keep all existing fields and form structure.

Improve their presentation.

Inputs should have:

* consistent height
* consistent border
* clear labels
* readable helper text
* clear focus state
* clear error state
* clear disabled state

Recommended default height:
40px

Improve spacing between:
label
input
helper/error message

Do not use placeholder text as a replacement for labels.

Long forms should feel structured and easy to scan.

# 7. CARDS AND CONTAINERS

Review existing cards and panels.

Reduce unnecessary card usage.

Do not put every section inside a visually heavy card.

Use cards only when they help communicate grouping.

Prefer:

* subtle borders
* very subtle elevation
* clean backgrounds
* moderate radius

Avoid:

* strong drop shadows
* excessive rounded corners
* nested cards inside cards
* excessive borders
* decorative gradients

# 8. BORDER RADIUS

Standardize corner radius.

Suggested direction:

Small UI elements:
6px

Inputs / Buttons:
8px

Cards / Panels:
10–12px

Dialogs:
10–12px

Avoid excessive pill shapes except for:

* tags
* status badges
* chips

The interface should feel modern but not overly soft or playful.

# 9. TABLES AND DATA

Do not change the existing data or column logic.

Improve table readability.

Focus on:

* cleaner headers
* better row spacing
* consistent alignment
* subtle dividers
* readable secondary metadata
* clear selected states
* clear hover states
* understandable status badges

Avoid visually heavy grid lines.

Tables should feel clean and professional.

# 10. STATUS DESIGN

Standardize statuses across the product.

Use:

icon + text + semantic color

Do not communicate status through color alone.

Status badges should use subtle backgrounds rather than highly saturated blocks.

# 11. NAVIGATION

Preserve the existing navigation structure and module organization.

Do not reorganize navigation.

Improve only:

* spacing
* icon alignment
* active state
* hover state
* typography
* hierarchy
* separators
* grouping clarity

Navigation should feel calm and easy to scan.

Selected navigation should be obvious without becoming visually heavy.

# 12. VISUAL HIERARCHY

Improve hierarchy on every existing page.

A user should immediately understand:

1. Where they are
2. What the page is about
3. What the primary action is
4. What information is most important
5. What actions are secondary

Reduce visual competition between elements.

Not everything needs equal visual emphasis.

# 13. ICONS

Use one consistent icon style across the application.

Prefer modern simple outline icons similar to Lucide.

Keep icon size and stroke visually consistent.

Do not mix unrelated icon styles.

Do not add icons when they do not improve comprehension.

# 14. EMPTY / LOADING / ERROR STATES

Where these states already exist, improve their visual consistency.

Do not change application logic.

Standardize:

Empty state
Loading state
Error state
Success state
Disabled state

Make error messages readable and actionable.

Avoid overly technical presentation for normal users.

# 16. ACCESSIBILITY

Improve accessibility without changing the existing product structure.

Ensure:

* sufficient color contrast
* visible focus states
* readable font sizes
* clear labels
* clear disabled states
* accessible status communication
* usable click targets
* understandable error states

# 17. REDUCE VISUAL NOISE

Audit every screen and reduce unnecessary visual noise.

Especially look for:

* too many borders
* too many cards
* excessive background colors
* excessive bold text
* inconsistent padding
* strong shadows
* unnecessary decorative elements
* inconsistent radiuses
* excessive visual separators

Do not remove useful information.

Only improve its presentation.

# 18. KEEP THE CURRENT PRODUCT IDENTITY

The final interface must still clearly feel like the current product.

Do NOT perform a complete visual rebrand.

Keep:

* current overall color direction
* current content
* current workflows
* current structure
* current business terminology
* current functionality
* current information architecture

Only upgrade the quality and consistency of how everything is presented.

Look for:

* inconsistent spacing
* inconsistent fonts
* inconsistent button styles
* inconsistent inputs
* inconsistent cards
* inconsistent table styling
* inconsistent status badges
* arbitrary colors
* arbitrary radius values
* poor alignment
* excessive shadows
* unnecessary borders

Fix these inconsistencies throughout the entire prototype.

The final result should look like the SAME PRODUCT, but as if it had been refined by an experienced senior product designer.
